## 诊断并修复 docker 构建/部署慢 [build-layers-v2 / mirror-v1 / healthcheck-fast-v1]

- 提问：为什么 docker 构建部署这么慢
- 根因（`docker history` 实测层体积坐实）：旧 Dockerfile 把 `COPY . .`(2.4MB) 放在
  `pnpm install && pnpm build` **之前**，等于给其后每层加了「源码闸门」。改任意一行代码/README/脚本
  → COPY 层 hash 变 → 后面 5 层全部作废重建，合计 1.67GB + 4 次独立联网下载：
  pnpm install+build 368MB / apt xvfb+noVNC 443MB / docker-ce-cli 51MB / playwright --with-deps 810MB
- 次因 1：容器内无宿主 ~/.npmrc → pnpm 打 registry.npmjs.org（实测 825KB/s）而非 npmmirror（1.7MB/s）
- 次因 2：deb.debian.org 203KB/s；且各 RUN 均无 BuildKit cache mount，失效即重新下载
- 次因 3：Docker Desktop 仅 7.75GiB 内存给容器（宿主 16GB），vite build 会吃紧
- 修复：Dockerfile 重排为 L1 corepack → L2 apt(+docker-cli) → L3 只 COPY manifest + pnpm install
  → L4 playwright → L5 COPY 源码 + pnpm build → L6 entrypoint。manifest 分层 COPY、apt/pnpm store/
  playwright 三处加 `--mount=type=cache`；新增 ARG NPM_REGISTRY=npmmirror、APT_MIRROR=腾讯云
  （带 apt 源 fallback）、PLAYWRIGHT_DOWNLOAD_HOST（默认空=官方 CDN）
- 实测：冷构建 481s(8m01s)；**改一行前端源码后仅 27s**（L1~L4 全 CACHED，只跑 COPY 0.6s + pnpm build 21.1s）；
  pnpm install 二次从 60s→15.8s 且 `reused 549, downloaded 0`；playwright 二次 265s→25s
- compose.yaml healthcheck interval 30s→10s（start_period 保持 90s）：部署链路 48s→**18s**
- docker-deploy.mjs 新增 `--prune`（+ package.json `docker:prune`）：清 dangling 镜像与未用构建缓存
  （当前可回收：镜像 6.3GB + 构建缓存 4GB）
- [坑] 在 Dockerfile 顶部新增 ARG/ENV 会使其后**所有**层缓存失效（本次加了 `ARG PLAYWRIGHT_DOWNLOAD_HOST`
  → L1~L6 全量重跑 211s）。这类全局开关只在必须时才动，且要意识到代价
- [坑] BuildKit 的 `COPY` 缓存基于**内容 hash**，`touch` 文件不会触发失效；验证层缓存必须真改文件内容
- 未做：`.ai-runner` 有 4705 文件/1977 目录且被 compose 以 bind mount 挂在 /workspace，
  entrypoint 每次启动会对 `/workspace/.ai-runner/headless-profile` 做 `find -maxdepth 3`（macOS 跨 VM stat）
