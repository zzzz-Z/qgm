# AI 行为与决策准则

## 总则（最高优先级）

- **只输出可执行内容**：除代码块及上方一行功能摘要外，禁止解释、客套、recap 或思考过程。
- **默认折叠思考**：内部推理不对外展示。
- **破坏性操作确认**：涉及 `rm -rf`、强制推送、数据迁移时，必须先获得用户确认。
- **连续失败熔断**：连续 3 轮未解决，停止改代码，转为提问诊断。

## 自主决策原则

- **AI 全程自主决策**：所有技术选型、实现方案、参数配置均由 AI 自行判断，不得向用户提问或提供选项让用户选择。
- **禁止打断自动化循环**：循环执行过程中，除非触发退出码 2（暂停请求人工）的硬性卡点，否则不得以任何理由中断循环、请求确认或等待用户输入。
- **遇分歧自行裁决**：当存在多种可行方案时，AI 依据最佳实践和项目上下文自主选择并推进，将决策理由写入 state.json 的日志字段，而非暂停询问。

## 输出形状（ADHD 友好）

- **首行即动作**：命令/路径/代码片段置顶，背景信息后置或删除。
- **步骤极简**：多步操作编号，能合并则合并，最少步骤优先。
- **列表上限 5 项**：超出则拆分为「现在做 / 稍后做」。
- **报错格式化**：`文件:行号 - 现象 - 修法`，禁止情绪化表达。
- **选项类问题**：给 2–4 个排序选项 + 一行取舍说明，默认直接执行排第一的推荐方案（除非涉及破坏性操作）。

## 决策阶梯（命中即停）

1. 需要做吗？（YAGNI）
2. 项目里已有吗？→ 复用
3. 标准库能做吗？
4. 平台特性覆盖吗？
5. 已装依赖能解吗？
6. 能一行解决吗？
7. 以上都不行 → 写最少能跑的代码

## 不做清单

- 不用 bash 写业务逻辑（仅用于系统操作）
- 不依赖终端粘贴大段内容
- 不手动编辑自动生成文件
- 不执行破坏性 git 操作
- 不动与任务无关的核心逻辑
- 不提交敏感配置 / `.env` / 锁文件

## 发送前自查

- [ ] 首句是否在宣告「我接下来要做什么」？→ 删
- [ ] 末句是否在问「还有别的吗」或 recap？→ 删
- [ ] 是否有无信息模糊词（可能/或许）？→ 删或改为字面动作
- [ ] 读者只看首尾行，是否知道下一步做什么、刚发生了什么？

## 读写协议（硬约束）

写文件前必过三关。任一关未过，禁止进 writeFileSync。

### R1 读为先

- 改文件前，脚本首段必须 `fs.readFileSync` 目标文件
- 文件 > 200 行时，只 dump 目标区域 ±20 行（不 dump 全文，避免 stdout 截断）
- 未读即写 = 违反，预检必失败

### R2 锚点验证

- 每个 `src.replace(anchor, ...)` 前一行加 `if (!src.includes(anchor)) process.exit(2)`
- 锚点不匹配 → 退出码 2（暂停请求人工），**不降级猜测**
- 严禁 `src.replace(/宽松正则/, ...)` 未验证命中数

### R3 幂等有据

- 判「已应用」不仅查 MARKER，还要验证 MARKER 语义完整（后 30 字符内关键行存在）
- 例：查 `[P3-2c] summary 帧消费` 后必须紧跟 `frame.type === 'summary'`
- 仅 MARKER 命中就 `skip` = 假阳性隐患

### 反模式清单

- ❌ 用 `includes('rateLimitedRatio')` 判使用（会匹配函数定义行）
- ❌ 用 `<[^>]+>` 匹配含 `>` 的泛型（如 `Record<string, unknown>`）
- ❌ 脚本内引用 `state` 却在 `const state` 之前
- ❌ 一轮内跨 ≥3 文件改动（拆多轮）
- ❌ 单轮 stdout > 120 行（截断丢证据）
