# 脚本编写与技术规范

## 核心原则

- **文件改动必须走脚本**：禁止手动编辑、口头描述、输出整文件让用户复制。
- **幂等 + 可回滚**：重复执行安全；备份到 `.ai-runner/backup/`；支持 `--rollback`。
- **自检断言**：关键结果逐条校验，失败 `process.exit(1)`；非平凡逻辑留可跑 check。
- **路径安全**：统一 `path.join(ROOT, ...)`，禁止字符串拼接。

## 脚本头部强制规范（Shebang + 元数据）

每个代码块第一行必须是 Shebang，第二行起紧跟元数据注释。此格式为会话摘要唯一数据源。

### JS/CJS 模板

```js
#!/usr/bin/env node
// @desc: 一句话说明本脚本做什么（必需）
// @why: 解决什么问题（必需）
// @plan: 本轮唯一子目标
// @state: state 文件相对路径（缺省 .ai-runner/state.json）
// @done: 收尾的机器可判定条件（非收尾轮省略）
```

### Bash 模板

```bash
#!/usr/bin/env bash
# @desc: 一句话说明本脚本做什么（必需）
# @why: 解决什么问题（必需）
# @plan: 本轮唯一子目标
# @state: state 文件相对路径（缺省 .ai-runner/state.json）
# @done: 收尾的机器可判定条件（非收尾轮省略）
```

> ⚠️ Shebang 必须是第1行，前后无空行；禁止硬编码路径；`@desc` 与 `@why` 缺一会被要求重试。

## 通道选择

| 通道     | 用途       | 特性                                      |
| :------- | :--------- | :---------------------------------------- |
| `js/cjs` | 改项目文件 | 内存 overlay 沙盒，失败零改动，成功可回滚 |
| `bash`   | 系统操作   | 走 shell，跑前工作台自动 git commit 兜底  |

## Bash 黑名单（命中即停）

禁止以下命令及其变体：`rm -rf` / `sudo` / `curl|sh` / `wget|sh` / `dd if=` / `mkfs` / `> /dev/sd*` / `git push -f` / `git reset --hard` / fork bomb。
注释/字符串中也需避开黑名单字面量，可用字符串拼接或动作描述替代。

## 输出符号规范

- ▶ 阶段 / ✓ 成功（绿） / ! 跳过（黄） / ⚠ 警告（黄） / ✗ 失败（红，stderr）
- 使用语义函数 `ok/skip/warn/err`，禁止裸打印。
- 失败时报出 `文件 + 行号 + 现象`，可直接 grep。
