## 智普清言应用接入架构分析

### 1. 核心事实

项目名"智普清言"（qgm = **Q**i**P**u **Q**ingYan）是一个 **AI 编码智能体工作台**，它本身**不提供大模型服务**，而是接入外部 AI 聊天网页作为"大脑"，然后把 AI 回复里的脚本拿到本地沙箱执行，形成 **AI ↔ 本地代码仓** 的自动化闭环。

**目标站点**：[headless-constants.ts](file:///Users/apple/web-ai-qgm/packages/core/src/headless/headless-constants.ts#L9) 里硬编码的

### 2. 两条接入通道（二选一）

### 4. 回复分类引擎（接入层最复杂的部分）

核心入口是 [headless-inject.ts 的 detectReplyInPage](file:///Users/apple/web-ai-qgm/packages/core/src/headless/headless-inject.ts#L25)，它被 `page.evaluate` 序列化到浏览器侧执行。分类优先级：

```
1. busy 检测        → kind:'error'   // 服务繁忙
2. rate 频控        → kind:'error'   // 消息过于频繁
3. stopped 检测     → kind:'stopped' // 生成被中止
4. limit 触顶       → kind:'limit'   // 会话长度上限
5. 回复标记扫描（首行独占标记行）：
   SCRIPT → 走 extractLatestScript（闭合门 + 内容门 + 白名单 js/bash + 多脚本支持）
   ASK / DONE / HANDOFF / TEXT → 直接走对应 kind
6. DOM→Markdown 反推：elToMd 重建代码块/标题/列表
7. script 门控：hasUnclosedStructureJs（结构闭合）→ hasExecutableContent（有效内容）
8. 去重基线：_baselineLastHash（FNV-1a 32bit，对抗 DeepSeek 虚拟列表回收）
```

**核心 DOM 选择器**（绑定 DeepSeek 站点）：

- 输入框：`textarea:not([readonly]):not([disabled]), [contenteditable="true"]`
- 消息块：`.ds-message`（用户气泡）、`.ds-assistant-message-main-content`（AI 回复）
- 登录态：`localStorage.userToken`

### 6. 三条设计红线（踩坑固化进代码）

1. **「inbox-poll 无头静默丢回复」**（virtual-list-baseline-v1）：DeepSeek 切了虚拟列表，`.ds-assistant-message-main-content` 块数会下降。旧版用"计数增长"判新回复 → 恒判无新回复。修复：改用最后一条 assistant 消息的 FNV-1a hash 作基线。

2. **「探针源码自指误报」**（limit-scan-strip-v1）：AI 把 `headless-inject-simple.ts` 源码用 ``` 围栏回填到会话里 → 探针扫整页 textContent 命中自己写的正则词表（`maximum context length`）→ 误报触顶 → 掐掉一整轮。修复：四类标记探针先剥掉 `<pre><code>` / `textarea` / `script` / `style`。

3. **「fill 成功但收不到回复」**（fill-verify-v2）：Playwright 的 `page.evaluate` 里 `textarea.value = xxx` 被 DeepSeek React 受控组件丢弃（同步回空），只有 locator.fill() + keyboard.press() 走真实输入链路。验证从"发送后等 600ms 采样"改为"只读宽限轮询 2.4s / 300ms"，绝不重复点击。
