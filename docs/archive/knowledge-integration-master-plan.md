## §2 诊断：四个结构性问题

### P1 — 注入率失衡（最严重）

`lessons.md` **155 条 / 113 KB**，注入预算 `LESSONS_BUDGET = 6000` **字符**且**从文件尾截断**
（`load-lessons.ts:66-88`）⇒ 实际进上下文 **≈ 5.3%**，**95 条 `[VERIFIED]` 基本不在场**。

窗口选择规则还带一层偏向：待复核条目占比封顶 `MAX_PENDING_RATIO = 0.4`
（`load-lessons.ts:70`）——**结构上优先喂未复核内容**，把最有价值的已验证经验挤在窗口外。

> **后果实例（本会话亲历）**：`「熔断后合法脚本也被 429 拒」` 这条**已被 `[REJECTED]`**
> （服务端成功即 `resetRejectStreak`，不持续封锁），但应用端在**三个不同轮次**重新推理并写进
> 报告——因为它读不到那条 REJECTED（在窗口外）。每次浪费整轮往返。

### P2 — 固定成本与任务无关

首问恒定携带 **39 KB**（SYSTEM.md 24.8 KB + AGENTS.md 14.1 KB），无论是改一行 CSS 还是
排查通道断链。`SYSTEM.md` 的 §1–§13 里，多数段落对单轮任务零信息量。

### P3 — 无检索层，沉睡知识全靠人记

**564 KB** 历史日志 + **84 KB** 冷存分析 + 22 篇正式文档 + 归档工单——**没有任何检索入口**。
要回答「上个类似问题当时怎么解的」，只能靠人记得它在哪个文件第几段。AI 侧唯一的「记忆」是
被注入的 5.3% lessons 与 39 KB 规则。

### P4 — 权威分级靠约定，缺机器守卫

`SYSTEM.md / AGENTS.md / MEMORY.md / lessons` 四者的分工（谁 SSOT、谁蒸馏、谁只留指针）
写在 lessons 头部与 `SYSTEM.md` 里，但**只有 `DOCS-INDEX` 有机器守卫**（`docs:verify` 双向校验）。
其余约定**无守卫能检测「同一事实在四处各写一遍且已漂移」**。

> **本次已发生一次近失**：新工单编号一度按计划写 `WO-20261007-06`，而该号已被应用端自拟
> 工单占用，实际顺延为 **08**。编号这类「跨文件一致性」目前纯靠人眼，无守卫。
>
> **注意（诚实标注）**：我一度以为 `MAX_PENDING_RATIO = 0.4`（实现上限）与守卫
> `WINDOW_PENDING_MAX = 0.6`（`sessionPromptLessons.node-test.ts:144`）是漂移——**核实后否证**：
> 二者是「实现上限 + 回归阈值留余量」的正当关系，非漂移。**这正是 P4 想防的形态**：
> 若无人工核实，一个假漂移就可能被写成真结论。

## §3 整合架构：三层归位

核心原则：**知识库是「检索层」，不是「真相源」**。SSOT 一个都不迁移。

```
┌─ L0 常驻层（每轮注入，硬预算）────────────────────────────────┐
│  SYSTEM.md「必读铁律」+ AGENTS.md「首轮/结构/命令」           │
│  + 技能发现块（≤6KB）+ lessons top-k（≤6KB，检索取相关）      │
│  特征：SSOT 原地不动；只把「每轮都必需」的部分留在这里         │
│  目标：39KB 固定 → ≤ 12KB（必读+检索）                        │
└───────────────────────────────────────────────────────────┘
             ▲ 检索取片段                    ▲ 检索取片段
┌─ L1 检索层（按需取，LLM Wiki 索引）───────────────────────────┐
│  索引对象 = 全量文档的「蒸馏页」（一文档一页 + 源指针 + hash） │
│  · lessons 每族一页（含 [VERIFIED]/[REJECTED]/[STALE] 状态） │
│  · docs/*.md 一文件一页（SSOT 仍在 docs/）                    │
│  · 冷存分析/归档工单/历史日志（按日/按单分页）                │
│  · SYSTEM §4-§13 / AGENTS 独有约束（按需查阅段）              │
│  特征：**过期页不得当事实** —— 每页带「源文件 + hash + 生成时间」，│
│        运行时校验失配 ⇒ degraded（不许静默给旧内容）           │
└───────────────────────────────────────────────────────────┘
┌─ L2 冷存层（不索引，仅归档保管）─────────────────────────────┐
│  原始 .jsonl 日志、changelog、compliance、备份                  │
│  特征：运行态，不入库、不索引；需要时人工/脚本直读              │
└───────────────────────────────────────────────────────────┘
```

**三条铁律**（沿用前篇「三条纪律」，此处升级为架构约束）：

1. **SSOT 不迁移**：`docs/` + `SYSTEM.md` + `AGENTS.md` + `lessons.md` 仍是唯一权威；
   Wiki 页是**派生索引**，删了 wiki 不影响真相。
2. **过期即降级**：Wiki 页必须带 `{src, hash, generatedAt}`；运行时源文件 hash 失配 ⇒ 标注
   `stale` 或直接不用，**不得把过期内容当事实喂回**（否则放大错误）。
3. **状态随条目入页**：`[REJECTED]`（已判假）必须随条目进 wiki，并在检索命中时显式提示
   「正文描述是错的、不要照做」——否则 wiki 会把判假结论当事实再喂一遍（P1 的旧坑复发）。

## §6 承重判据与变异要求（每个阶段）

**通用原则**（本项目一贯纪律）：判据必须**承重**——改坏实现必变红；不得依赖运行态；
不得只测机制不测调用点。

### 阶段 B（lessons 检索化）

- **判据 B1**：给定 `goal = "e2e 端口漂移"`，注入块包含该相关条目 → 通过；
  变异：把检索退回尾截断 ⇒ 该条目不在注入块 ⇒ **必红**。
- **判据 B2**：注入块**体积仍 ≤ 上限**（`LESSONS_BUDGET` 语义保留为上限，不是「必须装满」）。
- **判据 B3**：检索命中 `[REJECTED]` 条目时，注入文案带「不要照做」标记
  （不得只注正文）→ 变异：去掉标记 ⇒ **必红**。
- **判据 B4（承重前提）**：检索配置**请求期读取**，不得模块加载期缓存
  （否则测试注入失效 ⇒ 判据真空；同 WO-08 判据④）。

### 阶段 C（首问瘦身）

- **判据 C1**：首问体积回归 —— 必读块 ≤ 8 KB（实测断言），且**冻结清单**里的关键铁律
  **逐字仍在场**（清单化，不许漏条）。
- **变异 C1**：把某条必读铁律移到按需段 ⇒ C1 的冻结清单断言 **必红**。

### 阶段 D（REJECTED 前置）

- **判据 D1**：`goal` 命中已判假结论时，注入显式提示「此为 `[REJECTED]`，不要照做」。
- **变异 D1**：删掉提示 ⇒ **必红**。

### 阶段 E（文档镜像）

- **判据 E1**：wiki 页的 `{src, hash}` 与源文件一致；源文件改动后，同步器**检测到过期**
  并刷新（不得静默留旧页）。
- **变异 E1**：改源文件 hash 后不刷新 ⇒ 过期检测 **必红**。
- **判据 E2**：wiki 不可达时，检索入口返回 **`degraded`**（不得返回空结果）——
  空结果与「没启动」不可分（同 WO-08 判据②的降级纪律）。

> **判据不得依赖真实 19828**：本机未装（A0 未做）⇒ 依赖运行态的判据必红。一律用
> `node:http` 在 `127.0.0.1:0` 起 stub（同 WO-08 做法）。

## §7 风险与「明确不做」

### 风险登记

| 风险                     | 等级 | 缓解                                                                    |
| :----------------------- | :--- | :---------------------------------------------------------------------- |
| **Wiki 页过期被当事实**  | 高   | §3 铁律 2：`{src, hash}` 校验 + 失配降级；每次检索校验，不缓存结论      |
| **判假结论经 wiki 传播** | 高   | §3 铁律 3：状态随条目入页 + 检索显式提示                                |
| **GUI 常驻依赖静默死亡** | 中   | 阶段 G 纳入 pm2；降级必须显式（`degraded`）                             |
| **token 泄露面**         | 中   | token 只留服务端（`/wiki/*` 代理天然满足）；**绝不进 env 的沙箱可见面** |
| **SSOT 双源漂移**        | 中   | Wiki 只读派生；P4 的守卫缺口单列（见 §8 D5）                            |
| **体积推导的加成被高估** | 低   | §9 论证边界诚实标注；阶段 B 后以实测检索命中率校正                      |

### 明确不做

1. **不给沙箱开通用 `fetch`** —— 等于开放出站网络面，配合 `__AI__` 读能力构成数据外泄通道；
2. **不镜像技能库进 wiki** —— 技能是「可执行方法论」，双存必漂移；保持「name+desc 发现 +
   `loadSkill` 按需加载」的渐进式披露；
3. **不迁移任何 SSOT** —— `docs/` + `SYSTEM.md` + `AGENTS.md` + `lessons.md` 原地不动；
4. **不做「一键把检索结果注入当前对话」** —— 上下文污染风险，待观察后再议（同 WO-08 硬约束）；
5. **不为瘦身而删铁律** —— 阶段 C 只做「移位（必读→按需）」，不做「删除」；冻结清单守住。
