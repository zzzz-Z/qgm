## 段一（P0）：工单编号唯一性守卫

### 一.1 缺口（为什么需要）

全仓**无任何守卫**检查工单编号。近失案例已记录在 master plan §2 P4：
新工单编号一度按计划写 `WO-20261007-06`，而该号已被应用端自拟工单占用，实际顺延为 `08`。
编号这类「跨文件一致性」目前**纯靠人眼**。

### 一.2 「自我声明编号」的谓词（**实测确定，不得放宽**）

宿主侧实测（探针：`/tmp/crossfile-probe.cjs`，js 口径同 `verify-docs-index.cjs`）

- 用「文件前 40 行内出现即算」的宽谓词 ⇒ **13 条假重复**，**全部是交叉引用**
  （例：`docs/workorder-app-pitfalls-and-residual-risks-2026-10-07.md` 正文引用 `WO-20261007-01`）。
  宽谓词**不可用**。
- 收紧为下面两条后 ⇒ **21 个自我声明编号 / 真重复 0 / 编号日期与文件名不一致 0**（精确、可作基线）。

**谓词（定案）**：一个编号算「自我声明」，仅当它出现在

1. 文件**首个非空行**（即 H1 标题行），或
2. 元数据行 —— 行首匹配正则 `^\|\s*\*\*编号\*\*`（即元数据表里以 `| **编号** |` 开头的那一行，见于 WO-08 / WO-09）。

正文中的其它编号一律视为**交叉引用**，不参与唯一性判定。

### 一.3 断言

- **A1**：同一编号不得自我声明于 **≥ 2 个不同文件**。
- **A2**：编号内嵌日期（`WO-YYYYMMDD-NN` 的 `YYYY-MM-DD`）必须出现在**该文件名**里。
- 失败信息须给出：冲突编号、涉及的文件、以及「该号已被谁占用」的候选（照 `verify-anchors.cjs`
  的 `suggest()` 精神——失败时直接可照抄修复）。

## 段二（P0）：SSOT 指针失效检测

### 二.1 缺口（为什么需要）

现有三个守卫的覆盖面（宿主侧逐份读完）：

| 守卫                            | 覆盖                                               | **不覆盖**                               |
| :------------------------------ | :------------------------------------------------- | :--------------------------------------- |
| `scripts/verify-anchors.cjs`    | `anchors.json` 里**显式登记**的 `(file, contains)` | 未登记的指针                             |
| `scripts/verify-contracts.cjs`  | 契约漂移                                           | 文档间相对链接                           |
| `scripts/verify-docs-index.cjs` | **仅 `DOCS-INDEX.md` 自身**的链接（双向对账）      | **其它文档正文里的相对链接**             |
| ⇒ **缺口**                      |                                                    | **除索引外的所有 md 的相对链接**，零校验 |

**实测存量（宿主侧，同一探针；测量于本单落盘前 ⇒ 计 39 篇，本单加入后为 40 篇）**：全仓 39 个项目 md / **悬空 2 条**：

| #   | 位置                                                           | 目标                             | 定性                                                                 |
| :-- | :------------------------------------------------------------- | :------------------------------- | :------------------------------------------------------------------- |
| 1   | `docs/archive/workorder-app-runtime-artifact-2026-10-05.md:22` | `./review-verdict-2026-10-05.md` | **真悬空** —— 真文件在 `docs/review-verdict-2026-10-05.md`（上一级） |
| 2   | `docs/FRONTEND-REVIEW.md`                                      | `javascript:...`                 | **假阳性** —— `javascript:` 伪链接，须进 skip 表                     |

**第 1 条的教科书意义**：同一文件 **L209 / L215** 用的是**正确的**仓根相对写法
`docs/review-verdict-2026-10-05.md`。⇒ **同一文件内两种写法并存，其中一种已经腐化**，
而**没有任何守卫发现它**。这正是 P4 所说的形态。

### 二.2 定案

- **解析基准**：相对**所在文件**的 `dirname`（markdown 语义），**不是**仓根。
- **skip 表必须增补**（实测得出）：`javascript:` 前缀（与既有 `https?:|mailto:|#|data:` 同处跳过）。
- **口径必须同源，不得新造第二份**（项目铁律：两份副本必然各自漂移）：
  抽出 `scripts/lib/docs-scan.cjs`，导出 `collectDocs` / `SKIP_DIRS` / `SKIP_PATHS` / `extractLinks`；
  `scripts/verify-docs-index.cjs` 改为 `require` 同一模块（**删除其内部副本**）。
  回归要求：改造前后 `pnpm docs:verify` 输出**逐字一致**（`✓ 文档索引对账通过 (39 个项目文档…)`）、
  exit 0。
- **抽取前必须剔除代码**（**否则本单自身的示例就会被误判**——已自检踩到）：
  先删**围栏代码块**（三反引号包围）与**行内代码 span**（单/双反引号包围），再抽 `](…)`。
  实例：本文档「段二·附」的 diff 围栏里有 `](./review-verdict-2026-10-05.md)`，
  「段四」G3 行有 `](no/such/file.md)` —— 都是**示例文本**，不是真链接。
- **断言**：悬空数 = 0。失败信息给 `文件:行号 -> 目标`。

### 二·附（P0）：修掉实测到的存量悬空

`docs/archive/workorder-app-runtime-artifact-2026-10-05.md:22`

```text
- 上一轮的判决与逐条取证见 [`docs/review-verdict-2026-10-05.md`](./review-verdict-2026-10-05.md) 的
+ 上一轮的判决与逐条取证见 [`docs/review-verdict-2026-10-05.md`](../review-verdict-2026-10-05.md) 的
```

「保留存量白名单」只在存量无法立即修好时才用；本次不需要。

## 论证边界（诚实标注）

- 编号谓词（首非空行 + `| **编号** |`）成立于**当前 21 个工单的实际写法**；
  若将来有工单把编号只写在正文散文里，会被判为「无自我声明」而**漏检**。
