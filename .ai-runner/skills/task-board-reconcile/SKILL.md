## 为什么存在

**核心判据：凡是「漏了没代价」的规则，靠自觉必然衰减。**

项目里两种规则的存活率对比鲜明：

- 脚本头 `@desc/@why` —— 漏了 → 400 拒收 ⇒ **从不漏**
- 锚点校验 —— 漏了 → `session:start` exit 2 ⇒ **从不漏**
- 看板 `push → start → complete` —— 漏了 → **什么都不发生** ⇒ **反复漏**

实测形态（2026-10-06 同一会话）：

- 第一批 7 分钟：全链路完整，含 2 次 `fail` ⇒ **会做、也做得到**
- 第二批（被打断后）：4 项**全部零收口**，`push`/`start` 都发了

⇒ **漏的是「尾」不是「头」**；形态是「做完一轮完整收口后，被新输入打断 ⇒ 新批次收尾整体丢失」，
属**批次级注意力衰减**，不是逐项生命周期问题。

**因此**：修法必须是**批次收口检查**（问一次「这批还剩几项没收」），而不是**逐项自动化**。

## 明确不要做的（都有实测反证）

- **不要「DONE 时自动 complete 所有 running」**：`complete` 现为**移除**语义 ⇒ 把未完成项抹掉，
  面板变空、用户读成「都做完了」。这不是让看板与现实一致，是**用假状态覆盖真状态**，比漏登记更坏。
- **不要「自动 start 首项」**：一轮 push N 项，只有 AI 知道在做哪项；猜错 = 在面板上谎报你在做什么。
  **可自动化的只有副作用（收口），不是意图（在做哪项）。**
- **不要 `--strict` 拒收 DONE**：DONE 是协议终态与五条终止路径之一；拦下它 = 把「看板没登记」
  升级成「会话卡住」。对齐仓库既有语义：漏登记属「缺证据」而非「矛盾」⇒ 同 `warnings`/`degraded` 处理。

## 对账口径设计（唯一要做的）

产出**每回合的未收口数**（分母 = 清桶次数，不是 push 条目数），写入留痕通道使其可按 sid / 日期聚合。

### 三个承重陷阱（每一个都能让判据当场失效）

**陷阱 1 · 读错数据源 ⇒ 判据真空**

必须读**落盘主存储**（如 `bucketItems()`），**不得读合并视图**（如 `readTaskState()`）——
后者每次读都并入 `PLAN.md` 派生项，而 plan 项**不在 sid 桶里** ⇒ 「有 pending 未收口」**恒真**。

> 判据要承重，测试里**必须造 PLAN.md**：无它时两种读法结果相同，判据无法区分（实测：
> 不造 PLAN.md 时变异态仍全绿；造了之后变异态 `1 failed`）。

**陷阱 2 · 采样点跨进程 ⇒ 顺序无保证**

不要在客户端两个各自 fire-and-forget 的请求间做对账（对账 fetch vs 清桶 fetch，HTTP 顺序不可保证）。
**正解：把采样放进「清桶」这个动作自身**——读与清在同函数、同一次请求内 ⇒ 顺序天然正确，
不需要任何时序判据。

**陷阱 3 · 分母来源不区分 ⇒ 率只有真值一半**

清桶常有两个调用点（正常终止 / 新循环启动），请求体往往**逐字相同**。
正常序列是 `init 清 → push… → finish 清` ⇒ 每循环贡献**两个**样本，而 init 那次**几乎恒为 0**
（上一轮 finish 已删桶）⇒ 分母被稀释约一半。
**要求：清桶请求体加可选来源字段，指标只取「终止」那类。**
例外值得记：终止清桶常是 fire-and-forget，失败/崩溃时**只有** init 能采到残留——那些样本价值更高。

## 变异验证必须跨轮（否则假阴性）

写盘只落 overlay、仅脚本 exit 0 才整体落盘；而 `vitest` 是**独立子进程读真实磁盘** ⇒
**同轮内 write→test 读到的是旧版**，变异必然「仍绿」。

> 正确姿势：**第 1 轮改 + exit 0 落盘 → 第 2 轮跑测试 → 第 3 轮还原**。
> 本会话曾两次因此误判「判据不承重」。

## 落地顺序

1. **先摘证再收口**：现场只活到下一个清桶动作；先把时刻表留档（复制日志末尾几行），再逐项定性收口。
2. **逐项定性，勿一刀切**：已落地的 `complete`；**被推翻的必须 `fail`**（标 `complete` 是假状态）；
   有偏差的 `complete` 并**附偏差说明**。
3. **先建采集器、跑接线前基线**，再接对账——没有基线就无法证明接线有效。
4. **接线 ≠ 开闸**：加入口/补文档可以，**不要接进 preflight**，不要让它自动跑。

## 验收判据（须承重）

- **顺序判据**：把读取点挪到清桶之后 ⇒ 判据必须变红（否则接的是台永远读 0 的仪器）。
- **口径判据**：构造「只有 PLAN.md 派生待办、sid 桶为空」的回合 ⇒ 未收口数必须为 **0**。
- **正向判据**：push 3 项、complete 1 项 ⇒ 未收口数必须为 2，且快照含那 2 项 desc。
- **不阻断判据**：存在未收口项时，DONE 处理仍正常推进（不得拒收/异常/卡回合）。

## 关联

- 用户可见面已存在（面板「检测到 N 项未完成任务」提示），**不新增 UI**、不做假完成。
- 与 `lessons` 台账同源：**写作方不得自标状态**，只有复核方亲跑证据后才标。
